# Git-triggered rebuilds for preprocessing

## Context

The current `npm run watch` uses chokidar to detect file changes and rebuild `trip-data.geojson`. In the main "in the field" workflow, the watched directory is also a git repo with `receive.denyCurrentBranch updateInstead`. The user clones the repo onto a phone (Termux), batches up GPX/KML files while travelling, and pushes them back to the dev machine in batches of ~10 (a few MB).

The watch workflow works but has friction:
- The dev box runs watch + serve, with output piped to a local log file the user has to `grep` to see build outcomes.
- There's no feedback on the *pushing* side — the phone has no way to know whether the build succeeded.
- Coalescing logic in `watch.js` exists partly to dampen the multi-event burst that a multi-file `git push` produces.

A `post-receive` git hook eliminates all of that. It fires exactly once per push, after `updateInstead` has checked out the files. Because it runs inside `git receive-pack`, its stdout streams back to the pushing client as `remote: ...` lines — so `[BUILD] Starting` / `[OK]` / `[FAIL]` lines appear directly in the phone's `git push` output. No log file, no polling, no IPC.

This work adds a small **one-shot setup script** — `npm run git:enable` (file: `preprocessing/enable-git-rebuilds.js`) — that configures a directory for git-triggered rebuilds. It does not modify `watch.js`; chokidar mode stays as-is for active local editing. The two workflows are independent — chokidar mode for active local dev, git mode for the batch-push-from-phone case.

## Scope

In scope:
- New script `preprocessing/enable-git-rebuilds.js` that configures a watched directory for git-triggered builds.
- New npm script `git:enable` invoking it.
- Short docs additions in `docs/preprocessing.md` and `docs/developer.md`.

Out of scope:
- Any change to `preprocessing/watch.js`.
- Auto-detection of mode, run-mode flags, `--mode=git` plumbing.
- Uninstall flag (documented manually instead — YAGNI; revisit if it comes up).
- Hook-driven coalescing or commit-range-aware builds (the hook just runs the standard build).

## Behaviour

### `npm run git:enable -- -i <dir> [-o <out>] [-n <name>]`

Args mirror `watch.js` and `build-trip-data.js`:
- `-i, --input <dir>` (required) — directory to configure. Must be a git repo.
- `-o, --output <file>` (optional) — output geojson path. Defaults to `./demo/<OUTPUT_FILE>` (same default as watch).
- `-n, --name <name>` (optional) — trip name passed to the build.

Steps in order:

1. **Resolve & validate input.** Expand `~`, resolve to absolute path. Bail if not a directory.
2. **Verify git repo.** Check `<INPUT>/.git` exists and is a directory (skip the worktree case — not part of the target workflow). Bail with a clear message if absent.
3. **Set `receive.denyCurrentBranch updateInstead`** via `git -C <INPUT> config receive.denyCurrentBranch updateInstead`. Idempotent. Print what was set.
4. **Hook collision check.** If `<INPUT>/.git/hooks/post-receive` exists and does NOT contain the marker comment `# generated by nomad-path enable-git-rebuilds`, refuse and explain: tell the user the file exists and was not written by us, and to move or delete it before re-running. Exit non-zero.
5. **Write hook.** Generate `<INPUT>/.git/hooks/post-receive` with absolute paths baked in:
   ```sh
   #!/bin/sh
   # generated by nomad-path enable-git-rebuilds
   # do not edit by hand — re-run `npm run git:enable` to regenerate
   node <ABS_PATH_TO_BUILD_TRIP_DATA_JS> -i <ABS_INPUT> -o <ABS_OUTPUT> [-n <NAME>] 2>&1
   ```
   `chmod 0755`. Use the resolved absolute path of `build-trip-data.js` from `import.meta.url` so the hook keeps working regardless of where the user runs the npm script from.

   **Notes on the hook content:**
   - **No `exec`.** Plain invocation is enough — both pass node's exit code through and forward stdout/stderr identically; `exec` would only save one process layer. Reads simpler without it.
   - **`2>&1` (merge stderr into stdout).** `build-trip-data.js` writes `[OK]`/`[BUILD]` to stdout and `[FAIL]` to stderr. Git forwards *both* streams back to the pushing client as `remote: ...` lines, but stdout is block-buffered when piped (which it is here, under receive-pack), while stderr is unbuffered. Without merging, a `[FAIL]` from stderr can appear *before* earlier `[BUILD]`/progress lines from stdout. Merging at the source preserves emit order. Costs nothing; fixes a real ordering footgun.
   - **Output buffering.** With `2>&1`, all output flushes together when the node process exits — the pusher sees the build result as one block at the end of the push, not as a streaming dribble. This matches the workflow (the phone wants "push complete, here's what happened") so no further flushing changes are needed.
6. **Print next steps.** "Setup complete. Run `npm run demo` to start the dev server; push to this repo to trigger a rebuild."

No initial build is run — the user pushes (or runs `build:data` manually) when ready. Keeps the setup script's job purely about plumbing.

### Hook behaviour at push time

`receive.denyCurrentBranch updateInstead` does the working-tree checkout before invoking `post-receive`. The hook invokes `build-trip-data.js`, so:
- The build's stdout (with stderr merged via `2>&1`) goes to `git receive-pack`'s stdout, which git streams back to the client as `remote: ...` lines.
- Exit code propagates: a non-zero build exit causes git to report the push as having a failing hook (push itself succeeds — `updateInstead` already checked out the files — but the user sees the failure).
- `build-trip-data.js`'s existing atomic-write + unlink-on-failure guarantees still hold, since the hook just invokes it normally.

### Failure modes & messaging

| Condition | Behaviour |
|---|---|
| `-i` missing | Print usage, exit 1. |
| `-i` not a directory | "Error: input path is not a directory: \<path\>" |
| `-i` is not a git repo (`.git` absent) | "Error: \<path\> is not a git repo. Run `git init` there first." |
| `post-receive` exists without our marker | "Refusing to overwrite \<path\>: not written by nomad-path enable-git-rebuilds. Move or delete it and re-run." |
| `git config` call fails | Surface git's stderr; exit non-zero. |
| Writing the hook file fails | Surface fs error; exit non-zero. |

- **`preprocessing/enable-git-rebuilds.js`** — the script. Estimated ~100 lines including USAGE text. Uses:
  - `parseArgs` from `node:util` (same pattern as `watch.js`).
  - `expandPath` from `preprocessing/lib/paths.js`.
  - `OUTPUT_FILE` constant from `preprocessing/lib/config.js`.
  - `logFail` from `preprocessing/lib/log.js` (for consistent error formatting with the rest of preprocessing).
  - `spawnSync` from `node:child_process` for the `git config` call.
  - `fs.existsSync`, `fs.readFileSync`, `fs.writeFileSync`, `fs.chmodSync` for hook handling.
  - `import.meta.url` + `fileURLToPath` to resolve the absolute path of `build-trip-data.js` for embedding in the hook.

### Modify
- **`package.json`** — add one line to `scripts`:
  ```json
  "git:enable": "node preprocessing/enable-git-rebuilds.js"
  ```
  (Does not depend on `build:contract` or `build:demo` — this script generates no artefacts.)
- **`docs/preprocessing.md`** — add a short section "Git-triggered rebuilds" after the watch material. Cover: when to use it (batch-push workflow), the setup command, what gets installed, how to read build output on the pushing client (`remote: [OK]` etc.), how to undo manually (`rm .git/hooks/post-receive` + `git config --unset receive.denyCurrentBranch`).
- **`docs/developer.md`** — one row in the scripts table for `git:enable`.

### Not modified
- `preprocessing/watch.js` — untouched.
- `preprocessing/build-trip-data.js` — untouched. The hook calls it normally with the same CLI it already exposes.

## Verification

End-to-end manual smoke test (the real workflow):

1. Create a throwaway git repo: `git init /tmp/git-enable-smoke && touch /tmp/git-enable-smoke/.gitkeep && (cd /tmp/git-enable-smoke && git add . && git commit -m init)`.
2. Run `npm run git:enable -- -i /tmp/git-enable-smoke`. Verify:
   - `git -C /tmp/git-enable-smoke config receive.denyCurrentBranch` prints `updateInstead`.
   - `/tmp/git-enable-smoke/.git/hooks/post-receive` exists, is executable, contains the marker comment and the absolute path to `build-trip-data.js`.
3. Re-run the same command. Verify: succeeds (idempotent — same hook content, marker present so it's allowed to overwrite).
4. Hand-edit the hook to remove the marker comment. Re-run. Verify: refuses with the collision message, exits non-zero, hook is untouched.
5. Clone the repo elsewhere, drop a GPX file in, push back. Verify: push output contains `remote: [BUILD] Starting` and either `remote: [OK]` or `remote: [FAIL]`. Output geojson lands at the configured `-o` path.
6. Negative cases: run with `-i` pointing at a non-directory; at a directory that isn't a git repo; with no `-i`. Verify each prints the right error and exits non-zero.

No new automated tests in this work — the script is small, deterministic, mostly I/O against `.git/`, and the watcher-test harness epic (Future) is the right home for any integration tests that would touch this surface. A small unit test of the hook-content generator (a pure function from args → hook string) is worth adding if the function is easy to expose.
